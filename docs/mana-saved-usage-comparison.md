# Saved adjacent query-day counters — local, not released

Child-Safety can now compare one new dated child-counter snapshot with an already
saved snapshot for the exact preceding query-calendar day. Parent-Touch alone
communicates the qualified result in the existing chat, including an assistant-only
first contact. This adds no new agent, mobile operation, provider endpoint, source
schedule, payment/grant capability or token allowance.

The new default-disabled flag is **`MANA_FAMILY_USAGE_COMPARISONS_ENABLED=false`**.
It requires the governed dated-review and Parent-Touch manager profile. Source
cache **v8** and family **v30** capture the feature only on new admissions/jobs.
The existing 09:00/15:00 collector can supply new dated observations, but neither
this flag nor a history/status GET activates it. Existing native per-message
source tools keep their original contracts; no historical-query tool is added.

## What the comparison proves

The existing Admin API source supplies counter values with requested date labels.
Its period, provider timezone, foreground semantics and full app coverage remain
unverified. The new consumer compares **reported counters**, not proven daily
screen time, behavioral growth, causality or child danger.

Only identical app labels with exactly one returned counter in each of the two
adjacent query days are matched. Arithmetic is computed and validated by code.
Overlapping/ambiguous rows are not summed; missing apps are not zero. A partial
page never becomes a complete ranking or total. The original dates, collection
times and coverage remain in the frozen input. Child-Safety and Parent-Touch may
explain those precise differences, with a safe practical parent step, but may not
promise pagination, future missing rows, a refreshed source or actual device use.

An absent baseline does not cause an old API/Firebase read or manufacture a
comparison. It stays absent for that captured context. A later historical read
cannot replace the current head or retroactively upgrade an old review. Models
receive a minimized comparison view without family IDs or snapshot credentials;
the original own-child source proof remains in private SQL.

## Acquisition, capture and uncertainty

Source v8 adds `usage_comparison_admissions` (one immutable bit per new owning day
request) and `usage_comparison_heads` (one exact current/previous pairing per
parent/child). The existing source completion transaction freezes the pairing.
One indexed previous-day lookup reuses the family's saved page; no lifetime scan,
listener, previous-day backfill or additional external request is introduced.
Fresh connected-child ownership still gates acquisition and specialist admission.
Parent scope, exact day, family/child fingerprints and snapshot identity are
validated before the result can enter a review. Coalescing/deduplication, original
cooldowns/meters, unknown source holds and the four-source cap remain unchanged.

Normalized saved family pages repeat app labels for each counter and can exceed
the original HTTP body's size. The local saved-page read is explicitly capped at
1 MiB, then minimized to the exact child. Existing 64 KiB job-context and model
budgets still refuse oversized analysis; nothing is silently shortened. A new
regression reproduces the earlier 256 KiB refusal for a valid typed family page.
This correction adds no external volume or model allowance.

Family v30 adds `usage_comparison_jobs`, atomically bound to new review admission.
Old/disabled/in-flight source captures never acquire the comparison. Disabling
skips unsubmitted captured work, fences a late result after verified usage, and
preserves submitted unknown holds across restart/midnight. It never reissues a
lost source/model call or returns an unknown reserve as free capacity. Current
closed v30/source v8 retain the private history. Previous-reader refusal is not
functional rollback or permission to downgrade/restore old databases.

Parent-Touch notices preserve both query dates and the minimized arithmetic view.
Only an admitted comparison may carry two query labels; old one-date notices
retain their original omitted-field JSON. One shared question slot, urgent Safety
priority, independent contact/push permissions and quiet hours remain in force.
The limits remain **2000 raw parent tokens per parent/day** and **2000 global
Child-Safety tokens/day**. These small limits are not fleet-capacity acceptance.
