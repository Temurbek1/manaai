## Source and communication contract

An existing ownership-filtered MANA profile lookup or an already acquired shared
inventory page can supply a complete parent-child linkage observation. Completeness
requires the backend's `children_count` and an exact matching validated children
list. Missing counts are unknown, never an empty-family assertion. This opt-in
coverage marker is absent from old serialized profiles/pages; their hashes and
captures do not change.

Only a fresh, complete profile with zero connected child IDs can originate setup
help. A linked child is not necessarily online. A zero-linked profile is neither
chat inactivity, abandonment, churn, uninstall, danger nor trial eligibility.
The first message states when the profile was checked and offers help connecting
a child. Parent-Touch saves that one assistant message, its typed dated proof and
a parent-scoped question atomically, then optionally queues the existing separately
authorized neutral push. No fabricated parent message or second chat is created.

Independent Retention chat permission, verified recipient language/timezone, quiet
hours, opt-out, shared pending-question slot, urgent Safety priority and existing
outreach limits still apply. Profile access or subscription never supplies consent.
RU, Uzbek Latin/Cyrillic and English first-contact templates are supported.

The source freshness ceiling is 180 seconds; the invitation's question lasts at
most24 hours. Default policy adds at most 20 global outreach messages per rolling
day and a seven-day same-parent cooldown, sharing the existing Retention count.
One unchanged zero-link epoch never creates another invitation. Disabled or
cancelled epochs do not resurrect when flags/permissions are re-enabled. A known
connected-child observation or incomplete/unknown newer profile cancels pending
setup outreach. Older incomplete inventory pages cannot invalidate a newer head.
An authorization denial durably closes this consumer; no automatic source retry
or circuit reset follows.
