## Behavior and limits

A complete literal reminder request can select the existing reminder owner at
admission without a separate model call just to choose that owner. The full
original message still goes to the same strong model, with fresh matching parent
profiles and the existing strict reminder decision schema. Syntax is not semantic
acceptance. The model may refuse harmful content; no code-only reminder draft or
scheduling was introduced. Every valid draft still needs the exact parent's
separate confirmation. Delivery still performs its one-shot fresh ownership check.

The bounded grammar supports explicit ISO dates and unambiguous today/tomorrow
with HH:MM, RU/EN/Uzbek Latin/Cyrillic reminder commands, and explicit IANA/UTC/GMT
zones. Incomplete, mixed, unfamiliar or ambiguous requests keep the ordinary model
router, without clipped text. Missing zones remain proposed defaults requiring
confirmation. Ambiguous/nonexistent DST wall times are not guessed. Reverse Uzbek
requests whose leading task looks like an unsupported explicit zone fall back.

One private row binds the original request digest, captured date clock, proposed
zone and entire task. Newly selected manager rows record reminder ownership but
no fictitious provider call ID or provider usage for the skipped routing step.
Only the actual owning model receipt is charged. The owner receives the original
relative-date clock/proposed zone even after midnight or a contact-timezone change.
Accepted candidates retain the exact task, instant and zone; a shortened task or
changed date/zone is refused after verified raw usage is accounted.

Only new admissions capture this route. Old messages never acquire it when the
flag is enabled or a process restarts. Disabling it or losing its proof fences
unsubmitted work before model submission. Late verified usage is charged while
late decisions are discarded. Submitted unknown holds survive restart/day changes;
the next-day public quota's day-local reserve may be zero while its unresolved
request flag remains true and the original SQL hold is retained.

This is the same reminder lifecycle, single chat, confirmation slot, priority,
consent, caps and2000 raw parent /2000 global Safety tokens. No source refresh,
schedule, push, financial action, tariff grant, model downgrade, smaller output
floor or automatic model/source retry follows. Source collection windows remain
09:00/15:00 under their separate settings. The parser chooses an owning capability;
it grants no new data or action authority.
