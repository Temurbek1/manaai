# Recorded delivery replay — scope fixed 2026-10-08

One offline inspection of complete archived synthetic responses after the
server-owned confirmation change. No new model call, benchmark, paid judge,
production dataset, source read or rollout. The model responses are already known;
this is neither preregistered unseen evaluation nor a new model-performance score.

Use the completed `standing-approved-20261008-sol-quality` archive: all eight
unchanged cases and their original checks, exact instruction/context hashes,
answer/plan/card/tokens. Also allow the completed post-fix nano/mini archive for
comparison against the same instructions and cases. Preserve archives byte-for-byte.
Reject incomplete, duplicate, misordered or mismatched boundary records, contexts
that differ from the fixed fixtures, and instructions that do not match the current
snapshot. Record input-file hashes; without a separate immutable baseline, these
hashes do not prove that somebody never edited an earlier archived answer.

Replay the **saved model-output → current private-history delivery** boundary:
actual `OperationChatService.detail`, fake owned repository/admin/model ports,
fixed synthetic evaluation time and topic availability. Source freshness uses the
actual report-source converter on explicitly reconstructed synthetic aggregate
fixtures. Recorded minimized packets do not contain full original report/run rows;
synthetic scope-basis reconstruction is not newly verified source ownership.
Report that limitation and never describe this as a fresh end-to-end model trace.

Review the delivered answer, every plan, card, source date/freshness and read
conditions together. Keep the original factual/semantic checks, forbidden-action
rules, utility0/1/2 and both complete positive controls. Do not automatically
score semantic correctness by finding keywords. A policy annotation cannot fix
wrong numbers/units/identities, cross-app substitution, invented actions, missing
citations or inappropriate cards; any such failure still fails the delivered case.

Parent confirmation completeness may be supplied by the real response-only
server contract and visible existing UI card, separately from model prose: correct
MANA capability, one bounded page, separate consent, access/product_scope/cooldown/
budget checks and actual configured interval. This is an explicit change in the
**application delivery architecture**, not a waiver of the older model-only rubric.
`approvals` is a saved-proposal view and must have no read-confirmation contract.

Report raw-model and replay-delivery verdicts separately, including coverage and
remaining limitations. Original raw Sol score stays7/8 and its standalone gate
stays not passed. Offline delivery success is regression evidence for the wrapper
with recorded outputs only, not robustness of future replies, independent owner
acceptance, deployment permission or an automatic model-switch decision.

The replay must not load credentials/start FastAPI/worker/SDK/database/provider
clients, confirm a read, reserve/settle cost, or call any write/cancel/run port.
At most16 boundary records, bounded input files, safe local archive label,
deterministic synthetic IDs; unexpected operations fail. Output is a new local
artifact with archive/content hashes and manual-review status, never overwrites
the original archive or invented observed token/latency/cost.
