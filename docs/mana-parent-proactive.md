# Проактивный Parent-Touch: один чат и push

Это новая локальная реализация, не описание уже включённого production.
Действующий production `f8d095e` и его 32 публичных пути не обновлялись этим
инкрементом. Конверсия, первые исходящие обращения и push по умолчанию выключены.

## Поведение

Агент может начать разговор до первого сообщения родителя. Родителю пишет только
Parent-Touch, в ту же единственную историю по профилю MANA `parent_id`.
Child-Safety инициирует типизированный вопрос/уведомление, а агент конверсии —
разрешённое предложение. Внутренний агент не становится вторым отправителем.

Последовательность:

1. Backend передаёт проверенный язык и разрешения родителя.
2. Новые данные ребёнка/состояния аккаунта дают задачу соответствующему агенту.
3. Parent-Touch сохраняет сообщение и push-outbox одной SQL-транзакцией.
4. Worker фиксирует одноразовый claim, затем вызывает API push.
5. Телефон читает уже сохранённое сообщение через обычную историю чата.

Пустое сообщение пользователя не создаётся. До первого текста используется явно
переданный язык родителя — не язык ребёнка, не догадка модели и не фальшивый
«предыдущий разговор». Язык фиксируется на допуске сообщения.

## Backend API

База: `/api/v1/mana-ai`. Везде нужен отдельный backend bearer-токен родительского
сервиса; телефон напрямую его не получает. Backend определяет `parent_id` из своей
авторизованной сессии. Регистрация настроек не даёт доступа к чужим детям.

### Зарегистрировать язык и разрешения

```http
POST /api/v1/mana-ai/parent-touch/contact-context
Authorization: Bearer <MANA_PARENT_CHAT_BACKEND_TOKEN>
Content-Type: application/json
User-Agent: MANA-Backend/1.0
```

```json
{
  "parent_id": "123",
  "event_id": "87f2fb03-56c4-4996-94a5-2512f99a8e40",
  "revision": 1,
  "observed_at": "2026-10-21T09:00:00Z",
  "valid_until": "2026-10-22T09:00:00Z",
  "language": "uz-Latn",
  "timezone": "Asia/Samarkand",
  "safety_chat_consent": true,
  "safety_push_consent": true,
  "marketing_push_consent": false
}
```

ID и даты вымышленные. Передавайте реальные подтверждённые настройки, не копируйте
пример как разрешение связаться с клиентом. Поддержаны `ru`, `uz-Latn`, `uz-Cyrl`,
`en`. Срок явно ограничен семью днями. При изменении настроек повышайте `revision`
и передавайте новый `event_id`; старый идентичный event только возвращает свою
сохранённую квитанцию и не восстанавливает отменённое согласие.

Разрешения раздельные. `safety_push_consent=true` не разрешает рекламу; согласие
на маркетинговый чат дополнительно берётся из свежего состояния аккаунта конверсии.
OS-разрешение на push и бизнес-согласие должен проверить backend. Parent List не
возвращает эти поля — нельзя автоматически поставить `true` всем родителям.

Чтение настроек, без отправки:

```http
GET /api/v1/mana-ai/parent-touch/contact-context?parent_id=123
```

Если явного текущего контекста нет, новый проактивный Child-Safety turn не
запускается. Обычная переписка и сохранённая история остаются отдельным потоком.

### Получить сообщение в том же чате

```http
GET /api/v1/mana-ai/parent-touch/chat?parent_id=123&limit=30
```

Сообщение приходит в `messages` с `role=assistant`, без выдуманного пользовательского
текста. Сохраняется обычная привязка `message_questions`/`active_question`; ответ
родителя передаётся через `POST /parent-touch/messages` с действительным
`reply_to_question_id`. Один ожидающий вопрос за раз. Срочное safety-уведомление
может прервать ожидание, но не создаёт второй вопрос. Коммерческие предложения
не опережают ожидающие safety-задачи.

Новое детское наблюдение по-прежнему передаётся в свой `/child-safety/...` endpoint.
Обычному backend не нужно ещё раз создавать вопрос/делать доставку после каждого
анализа: это делает worker. Для внешней типизированной потребности остаётся
`POST /parent-touch/requests` от зарегистрированного агента, а не произвольный
пользовательский `agent_id` или готовый текст для рассылки.

### Проверить push

```http
GET /api/v1/mana-ai/parent-touch/notifications?parent_id=123&after=0&limit=20
GET /api/v1/mana-ai/parent-touch/notifications/<push_id>?parent_id=123
```

`turn_id` связывает push с уже сохранённым сообщением. Чтение не отправляет push
и не вызывает модель.

| Статус | Значение |
| --- | --- |
| `queued` | Локальная SQL-очередь, API push ещё не вызван |
| `submitting` | Попытка уже закреплена; повторять нельзя, даже после потери worker |
| `queued_by_provider` | API подтвердил очередь на положительное число устройств |
| `not_queued` | Подтверждённый отказ или ноль устройств |
| `unknown` | Результат отправки неизвестен; автоповтора нет |
| `suppressed` | До вызова изменилась доступность/настройки, истёк срок или исчерпан лимит очереди |

`queued_by_provider` **не означает** доставку на телефон, открытие или прочтение.
Зависший `submitting` после потери процесса также нельзя повторно отправлять:
нужна проверка оператором, не новый nonce. Ошибка push не удаляет сообщение,
не вызывает повторную генерацию и не превращает неизвестный исход в успех.

## Вызов существующего API push

Адаптер использует документацию `notify-parent-api-2026-10-16.md`:

```http
POST https://api.manakids.uz/api/v1/parent/notify-parent/<parent_id>/
Authorization: Bearer <JWT>
Content-Type: application/json

{"title":"MANA","description":"MANA chatida yangi xabar bor. Ilovani oching."}
```

JWT получается перед отдельной новой задачей через существующий login endpoint.
Логин/пароль читаются из конфигурации, не передаются в мобильное приложение.
Один claim — одна отправка, без retry, redirect или повторного login после отказа.
После ошибок авторизации новые claims временно приостанавливаются; перечитывания
Firebase/GA4 или повторного анализа от этого не возникает.

В push нет имени ребёнка, GPS, содержания разговора, диагноза или цены оффера —
только нейтральное сообщение на подтверждённом языке. Полный текст остаётся
в защищённом чате. Лимиты API: title 120, description 500 символов.

Существующий endpoint не принимает deeplink/`chat_id` в теле. Мобильной команде
нужно настроить открытие своего единственного чата из уведомления AI-agent;
серверная интеграция сама по себе не доказывает, что обработчик на телефоне готов.

## Конфигурация и закрытие

```dotenv
MANA_PARENT_TOUCH_PROACTIVE_ENABLED=false
MANA_PARENT_PUSH_ENABLED=false
MANA_PARENT_PUSH_QUEUE_LIMIT=1000
MANA_PARENT_PUSH_MAX_AGE_SECONDS=3600
MANA_PARENT_PUSH_DAILY_ATTEMPT_LIMIT=100
```

Для включения требуются существующие Parent-Touch/review-first/Child-Safety runtime,
отдельный backend-ключ и явные лимиты. Нет скрытого увеличения 2000 токенов чата
или общего бюджета Child-Safety. Push не использует модельные токены; модельная
подготовка safety-сообщения по-прежнему расходует её обычную квоту.

В маркетинге сохраняются quiet hours, отдельное согласие, cooldown и caps.
Перед push повторно проверяются opt-out, текущая бесплатная подписка и действительность
оффера. При оплате/отказе до claim устаревший push подавляется, история не стирается.

Private SQLite v8 добавляется к v6/v7 без переписывания старой истории и unknown
holds. Текущий код имеет закрытый v8-reader; старый production `f8d095e` не является
v8 rollback-reader. Нельзя откатывать базу поверх новой истории. Выключение флагов
не возобновляет старые попытки и не удаляет квитанции.

## Граница конверсии

Выдача 1–30 бесплатных дней Maxsus через agent-grant-tariff — не оплата и не
транзакция. Push также ничего не оплачивает. Скидка допустима только из реально
подтверждённого каталога; API бесплатных дней не создаёт скидку 15%.

Реальный ограниченный GET Parent List для ранее указанного тестового профиля вернул
200, но без `is_paid`, начала бесплатного периода, истории agent-trial, согласия,
языка и активности. Его `tariff_name`/`valid_until`/`payment_date` не позволяют
самостоятельно классифицировать платного клиента. До источника этих фактов нет
утверждения, что все реальные родители автоматически отслеживаются агентом.
