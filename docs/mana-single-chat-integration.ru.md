# Подключение агентов MANA к одному чату

Инструкция для backend и мобильного разработчика. Описывает выпущенные Parent-Touch
и Child-Safety, приложение `f8d095e`. Разрабатываемый агент конверсии пока не входит
в этот production-контракт.

**API:** `https://ai.360rec.uz/api/v1/mana-ai`  
**Swagger:** <https://ai.360rec.uz/docs#/mana-ai>

## 1. Как это устроено

```text
Родитель → backend MANA → Parent-Touch → один чат родителя
                                ↑
                           Child-Safety
                                ↑
                  новые данные ребёнка от backend MANA
```

Родитель общается только с Parent-Touch. Child-Safety анализирует данные и передаёт
внутренние результаты и вопросы Parent-Touch. Родителю не нужно выбирать агента,
открывать другие чаты или видеть внутренний ответ Child-Safety.

Один `parent_id` = одна история. `chat_id` создавать или передавать не нужно.
История хранится у AI-сервиса, а не в приложении или Firebase.

Это **MANA**, даже если в домене API указано `360rec.uz`. Не передавайте сюда семьи
360REC. `parent_id` — строка с числовым ID профиля родителя MANA/Firebase, не Firebase
Auth UID и не ID ребёнка.

## 2. Авторизация и ответственность backend

Телефон обращается к вашему backend, а backend — к AI API:

```http
Authorization: Bearer <ISOLATED_MANA_PARENT_CHAT_BACKEND_TOKEN>
Content-Type: application/json
User-Agent: MANA-Backend/1.0
```

Используйте **отдельный серверный ключ родительского чата**. Общий ключ inference
для этого не подходит. Ключ нельзя помещать в мобильное приложение или публичный JS.

Backend должен сам определить `parent_id` по авторизованной сессии пользователя.
Нельзя проксировать произвольный `parent_id`, присланный телефоном. Для анализа
передавайте только детей этого родителя; AI-сервис дополнительно проверяет связь.

Проверка доступности настроенных агентов:

```bash
curl --fail-with-body --silent --show-error \
  'https://ai.360rec.uz/api/v1/mana-ai/agents' \
  -H "Authorization: Bearer ${MANA_AI_BACKEND_TOKEN}" \
  -H 'User-Agent: MANA-Backend/1.0'
```

`MANA_AI_BACKEND_TOKEN` здесь — переменная окружения вашего backend/терминала,
а не название поля в JSON. Примеры ниже содержат вымышленные ID — замените их.

## 3. Открытие чата: получить историю

```http
GET /api/v1/mana-ai/parent-touch/chat?parent_id=123&limit=30
```

```bash
curl --fail-with-body --silent --show-error \
  'https://ai.360rec.uz/api/v1/mana-ai/parent-touch/chat?parent_id=123&limit=30' \
  -H "Authorization: Bearer ${MANA_AI_BACKEND_TOKEN}" \
  -H 'User-Agent: MANA-Backend/1.0'
```

Отображайте массив `messages` по порядку. У сообщения есть `turn_id`, `role`,
`content`, `created_at`, `status`. `role=assistant` всегда показывайте как
Parent-Touch, независимо от того, какой внутренний агент инициировал сообщение.

Для старой истории используйте `next_before_turn_id` из ответа:

```http
GET /api/v1/mana-ai/parent-touch/chat?parent_id=123&limit=30&before_turn_id=100
```

Не добавляйте один и тот же ответ повторно: идентификатор видимого сообщения —
пара `(turn_id, role)`. Одному turn могут соответствовать и текст родителя,
и ответ ассистента; у проактивного сообщения бывает только ассистент.

## 4. Отправка сообщения: рекомендуемый flow

### Шаг A. Сохранить сообщение

```http
POST /api/v1/mana-ai/parent-touch/messages
```

```json
{
  "parent_id": "123",
  "request_id": "3a7454f8-38d2-4e8b-b251-017970f48350",
  "message": "Ребёнок поздно ложится спать. Что посоветуете?"
}
```

На каждое **новое** сообщение создавайте новый UUID. Сохраняйте UUID и исходное
тело запроса до отправки. При потере HTTP-ответа повторяется **тот же UUID и то же
тело**, а не создаётся новое сообщение.

Максимальная длина `message` — 2000 символов. Поля `agent_id`, `chat_id`, `locale`
или данные датчиков в этот запрос не добавляйте. Ответный язык определяется по
сообщению родителя; для коротких нейтральных ответов учитывается язык переписки.

Сервис отвечает `202` и состоянием сообщения. Это ещё не готовый ответ нейросети.

### Шаг B. Дождаться результата

```http
GET /api/v1/mana-ai/parent-touch/messages/3a7454f8-38d2-4e8b-b251-017970f48350?parent_id=123
```

Поле `phase`:

| Значение | Что делать в приложении |
| --- | --- |
| `awaiting_review` | Сообщение сохранено; Child-Safety ещё проверяет контекст |
| `responding` | Parent-Touch готовит ответ |
| `completed` | Ответ находится в `response.answer`; обновить общую историю |
| `failed` | Показать контролируемую ошибку из `error_code`; остановить ожидание |
| `unknown` | Результат вызова неизвестен; остановить ожидание, не отправлять заново автоматически |

Проверяйте состояние, например, раз в 2 секунды только пока пользователь ожидает
этот ответ. Обрабатывайте `429` и `Retry-After`; не создавайте бесконечный polling
для всех родителей. Ожидание подготовки ограничено пятью минутами.

При `completed` можно сразу показать `response.answer`, но после обновления истории
нужно объединить его по ID, а не нарисовать второй раз. При повторном открытии
экрана восстановите известный `request_id` и прочитайте его состояние/историю —
не запускайте новое сообщение для восстановления старого.

Пока сообщение обрабатывается, второй запрос того же родителя может получить `409`.
На время ожидания отключайте повторную отправку той же задачи.

## 5. Как родитель отвечает на вопрос агента

В истории есть `active_question` и `message_questions`. Они связывают вопрос
с конкретным видимым сообщением Parent-Touch. Не рисуйте метаданные как отдельные
сообщения и не показывайте технические UUID родителю.

Когда родитель отвечает именно на показанный вопрос, backend добавляет его ID:

```json
{
  "parent_id": "123",
  "request_id": "6dc4604e-ff09-49fb-873c-45ff3fbcf6ad",
  "message": "Обычно он ложится около десяти вечера.",
  "reply_to_question_id": "2a4fecb8-12d8-4709-bbf2-a54a0be5f774"
}
```

Отправляется в тот же `POST /parent-touch/messages`. ID вопроса нужно взять
из фактического ответа API, а не из этого примера. Без поля `reply_to_question_id`
сообщение не считается автоматически ответом на открытый вопрос.

Не привязывайте к вопросу любой следующий текст вслепую: родитель может сменить
тему. Устаревшая, чужая или уже использованная привязка возвращает `409`.

Parent-Touch задаёт один ожидающий вопрос за раз. Остальные вопросы стоят
в очереди. Срочное уведомление Child-Safety может появиться между вопросом
и ответом, но не открывает второй вопрос.

## 6. Передача новых данных ребёнка в Child-Safety

Backend отправляет новые факты в конкретный endpoint. Например:

```http
POST /api/v1/mana-ai/child-safety/safety-monitor
```

```json
{
  "parent_id": "123",
  "child_id": 124,
  "request_id": "7af34c56-f70c-43ef-b774-e38d41ccabdd",
  "source_revision": "device-observation-001",
  "analysis": {
    "request_id": "device-observation-001",
    "occurred_at": "2026-10-20T09:00:00Z",
    "locale": "uz",
    "data_minimized": true,
    "subject": {
      "subject_id": "124",
      "age_band": "age_7_12",
      "timezone": "Asia/Samarkand"
    },
    "input": {
      "battery": [
        {
          "evidence_id": "battery-001",
          "observed_at": "2026-10-20T08:59:00Z",
          "percent": 15
        }
      ]
    }
  }
}
```

Это пример структуры, не текущие данные. Передавайте реальные даты наблюдений,
а не подставляйте время отправки. `subject_id` должен соответствовать `child_id`.
Для неизменившегося наблюдения не создавайте новые UUID в цикле.

Другие доступные суффиксы `/child-safety/`:

- `family-digest`
- `adaptive-screen-time`
- `location-intelligence`
- `smart-content-filter`
- `scam-privacy-shield`
- `ai-gaming-safety`
- `child-safety-assistant`
- `family-agreement`
- `behaviour-anomaly`

У каждого свой JSON-контракт в Swagger. Тело `safety-monitor` нельзя отправлять
во все остальные endpoints. Универсального `/analyze` нет.

`202` означает приём задачи, не готовый анализ. Для backend-диагностики:

```http
GET /api/v1/mana-ai/child-safety/assessments?parent_id=123&limit=20
GET /api/v1/mana-ai/child-safety/assessments/<job_id>?parent_id=123
```

Внутренний анализ не показывайте в чате вторым отправителем. Если требуется
уточнение или допустимое уведомление, worker передаст его через Parent-Touch.
Приложение увидит его в обычной истории `/parent-touch/chat`.

Не запускайте отдельный анализ по таймеру для тех же данных. Автоматической
загрузки всей Firebase/GA4 этим flow не включается: новые факты передаёт backend.

## 7. Внутренняя очередь вопросов

Для обычного потока Child-Safety вручную создавать вопрос и вызывать доставку
после каждого анализа **не нужно** — это уже делает worker.

Если backend явно передаёт вопрос от зарегистрированного Child-Safety:

```http
POST /api/v1/mana-ai/parent-touch/requests
```

```json
{
  "parent_id": "123",
  "child_id": 124,
  "agent_id": "child-safety",
  "request_id": "be653861-85f8-47eb-a05c-7ebcc0228759",
  "information_key": "sleep.schedule",
  "question": "Во сколько ребёнок обычно ложится спать?",
  "reason": "Нужно уточнить обычный режим перед оценкой изменения поведения.",
  "source_revision": "sleep-observation-001",
  "priority": 1,
  "observed_at": "2026-10-20T09:00:00Z",
  "expires_at": "2026-10-21T09:00:00Z"
}
```

Ответ `201` — вопрос поставлен в очередь, но ещё не отправлен родителю.
Передавайте реальные даты, окно — не более семи дней. Приоритет 0–3: выше раньше,
при равном приоритете — по очереди. Совпадающие потребности могут объединяться.

Просмотр: `GET /parent-touch/requests?parent_id=123&limit=20`.

Для отдельной явной backend-доставки существует `POST /parent-touch/deliver`:

```json
{
  "parent_id": "123",
  "request_id": "ef93781d-60e0-4e5a-9e2b-c92ae801d454"
}
```

Это может вызвать модель и расходует лимит Parent-Touch. Не вызывайте его
дополнительно к автоматической доставке в цикле; не генерируйте новые nonce после
ошибок. Для проактивной модельной доставки нужен ранее установленный язык родителя.

Произвольный новый `agent_id` не зарегистрируется через этот запрос. В текущем
production поддерживаются Parent-Touch и Child-Safety. Будущие агенты подключаются
на сервере с собственными типизированными контрактами и политикой, а не под видом
Child-Safety и не с фиктивным `child_id`.

## 8. Лимиты и ошибки

На текущем production:

- Parent-Touch: **2000 input + output токенов в день на родителя**, включая
  системный контекст и ассистентские доставки, не только видимый текст.
- Child-Safety: **2000 токенов в день суммарно на всех родителей**. При резерве
  2000 на задачу это обычно около одного короткого анализа в день.
- Дневная граница — полночь `Asia/Tashkent`, то же местное время Узбекистана.

Маленький общий лимит Child-Safety может остановить новый ответ даже при наличии
остатка квоты Parent-Touch. Review-first не обходит этот отказ и не запускает
независимый анализ другим агентом. Массовую доступность чата с таким лимитом
обещать нельзя.

Квоты чата находятся в ответе истории; аналитический бюджет:

```http
GET /api/v1/mana-ai/child-safety/budget?parent_id=123
```

| HTTP | Обработка |
| --- | --- |
| `401` | Проверить отдельный backend-токен |
| `403` | Не продолжать: нет подтверждённого доступа к ребёнку/данным |
| `404` | Нет такой задачи в контексте этого родителя |
| `409` | Конфликт UUID, выполняющаяся задача или неверная привязка ответа |
| `422` | Исправить поля по конкретной схеме Swagger |
| `429` | Учитывать квоты и `Retry-After`; не обходить новым UUID |
| `502/503` | Контролируемая ошибка модели, источника или отключённой функции |

GET истории/состояния не вызывает модель и не повторяет исходную задачу. Потерянный
ответ модели не считается бесплатным: `unknown` сохраняется без автоповтора.
Чат не гарантирует экстренную доставку и сам не отправляет push или команды
управления телефоном ребёнка.

## 9. Что нужно сделать в приложении

1. Один экран чата: история, поле ввода, отправка, состояние ожидания.
2. На backend — защищённый proxy с получением своего `parent_id` из сессии.
3. Отправка через `/parent-touch/messages`; получение результата по `request_id`.
4. Привязка действительных ответов к `reply_to_question_id` без показа UUID в UI.
5. Передача только новых детских событий в соответствующие Child-Safety endpoints.
6. Обновление истории при открытии/возврате в чат и ограниченное наблюдение,
   пока чат открыт. Родительские SSE/WebSocket этим API пока не предоставлены.
7. Дедупликация по `(turn_id, role)`, обработка лимитов и отсутствие автоповторов
   платных или неизвестных задач.

Агент конверсии разрабатывается отдельно. Его новые `/conversion-agent/...`
маршруты, выдачу бесплатных дней и предложения тарифов не подключайте как уже
выпущенные endpoints, пока не будет отдельного подтверждения выпуска.
